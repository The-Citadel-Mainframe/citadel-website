    2026-11-20 // Report 01
    
Project intents and status

    

    
First report. It defines CitadelOS and Cortega, lists the intents of the project, and states which components are validated and which are not. It is based on the project documents up to 2026-11-20.


    
Section // What is CitadelOS
    

      
CitadelOS is an operating system independent from Android. It is developed in Go, using only the standard library, and builds for linux/arm64 and linux/amd64.

      
Intents

      
    
        
  • Independence from Android. No Android framework. Own init (citadel-init, PID 1). Static Go userspace.
    • 
        
  • Anonymous network as the only path. All Internet traffic goes through Tor. There is no alternative path.
    • 
        
  • Recognition between Citadel devices on the LAN only. Two devices recognise each other as OPERATOR-N, where N is random and regenerated at every scan. No persistent identifier, no MAC address, no hostname is exposed.
    • 
        
  • Network Discovery (cnd). Scans authorised networks. Non-Citadel devices stand out by difference. The gateway is labelled "mother".
    • 
        
  • Interface. Aesthetics derived from this website. Command autocompletion for inexperienced users.
    • 
        
  • Zero cost. No paid APIs, no telemetry.
    • 
      

    

    


    
Section // What is Cortega
    

      
Cortega is the local AI assistant of CitadelOS. It interprets requests in natural language and translates them into system commands. It operates only within the Citadel perimeter.

      
Intents

      
    
        
  • Model. Qwen3-0.6B (Apache-2.0), run locally with llama.cpp on the loopback interface. No upload, no telemetry.
    • 
        
  • Precision profiles, chosen by the operator: ECO (Q4_0), STANDARD (Q8_0), PRECISION (f16 or BF16).
    • 
        
  • Constrained output. The model emits only an intent in JSON, {action, target, detail}, taken from a closed list of actions and enforced by a GBNF grammar. Risk and confirmation are decided by the code, not by the model.
    • 
        
  • Mandatory confirmation. Every executable action requires confirmation from the operator. port_scan and discover_hosts require the word CONFERMA.
    • 
        
  • Perimeter. For Cortega the world is Citadel. She answers about Citadel, CitadelOS and herself. Friendly conversation is allowed. Topics outside the perimeter are refused by the code, without querying the model.
    • 
        
  • Grounded answers. Local knowledge base with BM25 search. Answers include their sources.
    • 
        
  • Learning as a spectator. She reads this website and the public YouTube channel, without login, only through Tor, only from allowlisted hosts. Learned content is treated as untrusted data and cannot issue actions.
    • 
        
  • Networks. Only IP addresses inside authorised networks. No hostnames.
    • 
        
  • Generated tools. Saved and analysed statically, never run automatically. Execution only with /run, confirmation and a timeout.
    • 
        
  • Audit. Date, outcome and type of action. Never the text of the target.
    • 
      

    

    


    
Section // Principles
    

      

        
Anonymity
All traffic through Tor. No persistent device identifier. No telemetry.

        
Human control
Every executable action is confirmed by the operator. Risk is decided by code. The AI of Father waits for human input and does not act autonomously.

        
Perimeter
Cortega works only inside Citadel. Only authorised networks and allowlisted hosts. Learned content cannot issue actions.

        
Zero cost
No paid APIs. Local execution of the model.

      

    

    


    
Section // Editions: Operator and Father
    

      
CitadelOS has two editions: Operator, a field device, and Father, a control station. The current priority is Father. Operator is in backup and its resumption is postponed.

      
Citadel Father

      
    
        
  • Role. Control station to which operators connect. Target hardware: laptop LX15PRO (Ryzen 7 5700U, 16 GB).
    • 
        
  • Operator link. Direct LAN and Tor onion service. TCP handshake with an HMAC-SHA256 proof.
    • 
        
  • Signed directives. Ed25519 signatures. Allowed actions: ping, status, scan_lan, message. Expiry after 60 seconds, anti-replay. The operator verifies with the public key only.
    • 
        
  • Local interface. Web UI served by Father: HTTPS, access token, HttpOnly and Secure cookie, limit on login attempts. A dedicated graphical shell is planned.
    • 
        
  • Base. Debian 13 stable. Go services run as systemd units: citadel-father, citadel-llama, citadel-cortega.
    • 
        
  • Device management (citadel-devd). Coldplug and hotplug, automatic loading of kernel modules, device registry.
    • 
        
  • OS–AI symbiosis. Project goal: desktop and drivers that adapt to what is connected.
    • 
        
  • Human input. The AI of Father always waits for human input and does not act autonomously.
    •

Section // Declared limits
    

      
    
        
  • Operator hardware target suspended: bootloader unlock failed. Alternative devices are being evaluated. No ARM hardware is currently available.
    • 
        
  • A single fleet key is shared by the whole fleet: no revocation for a single operator. Accepted choice.
    • 
        
  • Quality of the answers of Qwen3-0.6B, tokens per second and thermal behaviour: not measured.
    • 
        
  • Wi-Fi (8852BE), amdgpu, NVMe and Secure Boot on the LX15PRO: not verified.
    • 
        
  • /run has no operating-system-level isolation. The static analysis is heuristic.
    • 
        
  • The perimeter filter is lexical: external topics that use only words present in the knowledge base can pass.
    • 
        
  • The web UI certificate is self-signed: the browser shows a warning at first access.

    2026-11-22 // Report 02
    
Citadel Father on Debian 13

    

    
Second report. Citadel Father now runs as a control station on Debian 13 stable, inside a QEMU virtual machine on the LX15PRO. It does not exist on real hardware yet. Indicative completion: about 50 percent (method at the end of this report).


    
Section // What was done
    

      
Base and virtual machine

      
    
        
  • Debian 13 installed in a QEMU VM (UEFI). Systemd services for Father, the local inference server and Cortega.
    • 
        
  • Father services from the previous reports: operator handshake, Ed25519 signed directives, anti-replay, 60 second expiry, audit without target text, web UI over HTTPS with access token.
    • 
        
  • citadel-devd (coldplug and hotplug of kernel modules): validated in QEMU, never on real hardware.
    • 
      

      
Citadel desktop

      
    
        
  • Theme taken from this website: centred emblem as wallpaper, VT323, Cyber Blast and Terminal Grotesque fonts. Themed login screen and themed GRUB.
    • 
        
  • XFCE session without panel. Desktop icons drawn in detailed ASCII: Trash, File manager, Resources, Terminal, AI Terminal, Network, Browser.
    • 
        
  • Italian keyboard layout script prepared.
    • 
      

      
Cortega in Father mode

      
    
        
  • Father-only profiles, visible only when Father mode is enabled and never chosen by automatic selection.
    • 
        
  • In Father mode the default scope is Father. Answers are grounded when the knowledge base supports the question, otherwise free, with a Father prompt. The gate on authorised networks, the policy and the fixed reply to authority claims stay in the code.
    • 
        
  • Local inference with llama.cpp, static binaries. A basic build runs on any x86_64 CPU but is very slow. A faster build needs AVX2, which the VM must expose.
    • 
        
  • The AI of Father still waits for human input and does not act autonomously.
    • 
      

      
Network and Tor

      
    
        
  • citadel-net with three modes. Off blocks every outbound connection. Tor lets out only the Tor user. On is free, for updates. The system starts offline.
    • 
        
  • citadel-tor-check verifies the Tor circuit. The AI Terminal learns online only if the check succeeds, otherwise it uses the local cache.
    • 
        
  • Browser. Firefox ESR with a policy: SOCKS proxy locked to Tor, DNS through the proxy, WebRTC and geolocation off, fingerprinting resistance on. Google via Tor can show a CAPTCHA: no bypass is implemented.
    •

    2026-11-25 // Report 03
    
Father in the VM: installer, onion operators and node-map interface

    

    
Third report. Citadel Father still runs only inside a virtual machine. It now has a single installer, a local certificate authority, one identity per operator, updates through Tor only and an interface built on a node map. Readiness is 70 percent, 52 of 74 items closed, measured with the method described at the end.


    
Section // Installer, services and web UI
    

      
Installer

      
    
        
  • Single installer. One installer sets up Father on Debian 13, in steps 0 to 11 with a check at every step. It ran with all steps OK inside the VM.
    • 
        
  • Kit. Old versions, old binaries and the old operator knowledge base were moved out of the kit. Documents and installation guide are aligned. One start script remains for the VM: 8 CPUs, 6 GB of RAM, full HD.
    • 
        
  • Services. The local inference service and the Cortega service are now enabled by the installer. The inference server had gone missing after an earlier install; the new installer restores it. Verified: health check OK and Cortega answers.
    • 
        
  • citadel-father as a service. It exited immediately under systemd: its interactive console read an empty input and returned status 0, so no restart happened. A daemon flag now starts it without the console. Verified in the VM, with the web UI reachable.
    • 
        
  • VM restart. A guest reset used to stop the emulator and leave a frozen screen. The start script now asks "restart the VM?" and reopens it. Verified.
    • 
      

      
Web UI

      
    
        
  • Local certificate authority. Father generates its own Citadel CA and signs the web UI certificate with it. The CA is trusted in the browser of Father only. On other machines the browser warning remains, by choice. Verified.
    • 
        
  • Confirmation. scan_lan and message sent from the web UI require typing CONFERMA. Authorising and revoking an operator require it too. Verified.
    • 
        
  • Sessions. Web UI sessions last 1 hour and survive a restart of the service. Only hashes of session ids are stored on disk. Verified.
    • 
      

    

    


    
Section // Network, Tor and operators
    

      
Tor and updates

      
    
        
  • apt through Tor. Updates come only from the official Debian onion mirrors, through apt-transport-tor. They work in Tor-only mode, and resolving the clear-net mirror fails, as intended. Verified.
    • 
        
  • citadel-net. A bug is fixed: without administrator rights the status command printed "on" instead of the real mode. Verified.
    • 
        
  • Onion service of Father. It publishes only the operator port. The web UI is not published on Tor. An operator reached Father through the onion address. Verified.
    • 
      

      
Operators

      
    
        
  • One identity per operator. Handshake v2: the operator signs the challenge of Father with its own Ed25519 key. Father checks the signature and that the key is in the authorised list, then answers with its own signature, which the operator verifies. Unauthorised operators are refused and audited by id only.
    • 
        
  • Revocation. Removing an operator from the list closes its sessions at once and blocks reconnection. The shared fleet key is kept only for recognition on the LAN. Verified from Father Signals: authorisation with CONFERMA, connection through onion, verified ping, revocation, refused reconnection.
    • 
        
  • Authorisation requests. An operator with a valid signature but an unknown key appears in a REQUESTS screen of Father Signals, up to 20 requests, kept for 24 hours. Father can authorise it with CONFERMA or ignore it.
    • 
      

      
Cortega as operator

      
    
        
  • Link to Father. Cortega connects to Father at every start, with retries every 10 to 60 seconds. A received directive is shown to the user. /esegui N runs it only through the gates and always asks for CONFERMA. /rifiuta N discards it. The first connection appears in REQUESTS.
    • 
        
  • Signature of Father. The Father package of Cortega now verifies the Ed25519 signature of Father. The old HMAC is gone.
    • 
        
  • Cortega operator test. A test inside Father runs 7 steps with a temporary key. Result: 7 of 7 OK. Start 207 ms, refusal through onion 3843 ms, connection after authorisation 11072 ms, status to ack 443 ms, ping to ack 320 ms. The test leaves no trace: its key is never added to the authorised list.
    • 
      

    

    


    
Section // Cortega
    

      
    
        
  • Router. The intent router now passes 35 of 35 test sentences, up from 34 of 35. The request to create a script that shows date and time is now read correctly. The larger precision profile is the new default.
    • 
        
  • Generated tools. Sum of 1 to 100: 20 seconds in total, one version, output 5050 correct. Prime numbers below 30: 38 seconds, one version, output correct. The isolation of /run is active in the VM.
    • 
        
  • Speed. Start of the AI Terminal in 10 to 15 seconds. Prompt reading at 117 tokens per second. Generation speed was not read. The desktop stays fluid while Cortega generates.
    • 
        
  • Inference engine. Decision: llama.cpp stays pinned for Father. No own engine in Go.
    • 
      

    

    


    
Section // Node-map interface
    

      
Citadel OS Father now follows one interface idea: a node map in red and black ASCII. The overworld leads to the programs, and each program has its own map.

      
    
        
  • Overworld. Full-screen map: CITADEL leads to PROGRAMS (AI Terminal, Terminal, Files, Browser), FATHER SIGNALS, NETWORK (Off, Tor only, Free with CONFERMA, Tor status) and SYSTEM (Resources, Keyboard and screen, Animation, Restart and Shutdown with CONFERMA). A program opens maximised above the map, and closing it returns to the overworld. The transition dissolves the map into falling characters and recomposes it.
    • 
        
  • Workspaces. SYSTEM, SPACES, SPACE 1 to 4, with the active one in green.
    • 
        
  • Emblem. The CITADEL node, the wallpaper, the login screen and the boot splash use an ASCII version generated from the original Citadel logo. In the boot splash the emblem recomposes from falling characters. Verified.
    • 
        
  • Top bar. A single ASCII line: program, windows, space, network, CPU, RAM, AI, date and time. Verified.
    • 
        
  • Father Signals. Opens the web UI of Father already authenticated, without typing the token. Its home is an ASCII node map: OPERATOR NETWORK (connected, authorised, directives, requests), SETTINGS AND BENCHMARK, AUDIT. Operator windows offer STATUS, PING and MESSAGE buttons. Verified.
    • 
        
  • Benchmark. Three tests, with 1 to 5 repetitions and a stored history. Operator test through onion: circuit 424 to 610 ms, handshake 408 to 512 ms, directive and ack 512 to 518 ms, total 1352 to 1535 ms. Tor and SOCKS: check of the Tor circuit in 803 to 943 ms, Tor confirmed. Debian onion mirror: OK. Measured in the VM.
    • 
        
  • Animation load. The map now draws on a canvas with pre-rendered glyphs. In a test container the CPU use of the web engine fell from 82 percent to 15 percent. A setting offers full (10 frames per second), reduced (4, no rain) or off. Not yet measured in the VM.
    •
