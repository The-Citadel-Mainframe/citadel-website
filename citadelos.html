CitadelOS & Cortega


Development log of CitadelOS, an operating system that does not depend on Android, and of Cortega, its AI assistant that runs on the device. Reports are in order: the oldest at the top, the latest at the bottom. Each report says what has been checked and what has not.

    2026-11-20 // Report 01
    
Project intents and status

    

    
First report. It explains what CitadelOS and Cortega are, what we want to build, and what already works and what does not. It is based on the project documents up to 2026-11-20.


    
Section // What is CitadelOS
    

      
CitadelOS is an operating system that does not depend on Android. It is written in Go and runs on both ARM and x86 processors.

      
Intents

      
    
        
  • No Android. It has its own base and does not use any part of the Android system.
    • 
        
  • Internet only through Tor. All Internet traffic goes through Tor, an anonymity network. There is no other route.
    • 
        
  • Citadel devices recognise each other on the local network. Two devices see each other as OPERATOR-N, where N is a random number that changes at every scan. No fixed ID, no hardware address and no device name is shown.
    • 
        
  • Network scanner. It scans only networks we authorise. Devices that are not Citadel stand out. The router is labelled "mother".
    • 
        
  • Interface. The look comes from this website. Commands are autocompleted, to help people who are new to the terminal.
    • 
        
  • Zero cost. No paid services and no tracking.
    • 
      

    

    


    
Section // What is Cortega
    

      
Cortega is the AI assistant of CitadelOS and runs on the device itself. You write in plain language and it turns your request into a system command. It only works inside the Citadel world.

      
Intents

      
    
        
  • Small local model. It runs on the device and sends nothing out. No uploads and no tracking.
    • 
        
  • Three precision levels, chosen by the operator: ECO (fastest, least precise), STANDARD, and PRECISION (slowest, most precise).
    • 
        
  • Limited output. The AI can only pick an action from a fixed list. The program decides how risky an action is, not the AI.
    • 
        
  • Always asks first. Every action needs the confirmation of the operator. Scanning actions need the operator to type the word CONFERMA.
    • 
        
  • Stays on topic. Cortega talks about Citadel, CitadelOS and herself. Friendly chat is fine. Anything else is refused by the program, without even asking the AI.
    • 
        
  • Answers with sources. She looks things up in a local knowledge base and shows where each answer comes from.
    • 
        
  • Learning by reading. She reads this website and the public YouTube channel, only through Tor and only from approved sites. What she reads is treated as plain information and can never give her orders.
    • 
        
  • Authorised networks only. She works only with addresses inside networks we authorised.
    • 
        
  • Tools she writes. They are saved and checked, but never run on their own. They run only if the operator asks and confirms, and a time limit applies.
    • 
        
  • Activity log. It records the date, the outcome and the type of each action, never the text of the target.
    • 
      

    

    


    
Section // Principles
    

      

        
Anonymity
All traffic goes through Tor. No fixed device ID. No tracking.

        
Human control
Every action is confirmed by a person. The program judges the risk. The AI of Father waits for a human and never acts on its own.

        
Perimeter
Cortega works only inside Citadel, on authorised networks and approved sites. What she reads cannot give orders.

        
Zero cost
No paid services. The model runs locally.

      

    

    


    
Section // Editions: Operator and Father
    

      
CitadelOS comes in two editions: Operator, a device used in the field, and Father, a control station. Right now the focus is Father. Operator is set aside and will resume later.

      
Citadel Father

      
    
        
  • Role. The control station that operators connect to. Target machine: the laptop LX15PRO.
    • 
        
  • Connection with operators. Through the local network or through Tor. Every connection starts with a secret check.
    • 
        
  • Signed orders. Father sends orders with a digital signature. Allowed orders: ping, status, network scan, message. An order expires after 60 seconds and cannot be replayed. The operator only needs the public key to check it.
    • 
        
  • Local interface. A web page served by Father, protected with HTTPS, an access token and a limit on login attempts. A dedicated graphical interface is planned.
    • 
        
  • Base. Debian 13, with the Citadel services running on top of it.
    • 
        
  • Device management. Father detects devices when they are plugged in and loads the right drivers by itself.
    • 
        
  • OS and AI together. The goal is a desktop and drivers that adapt to what is connected.
    • 
        
  • Human first. The AI of Father waits for human input and does not act on its own.
    •

Section // Declared limits
    

      
    
        
  • The hardware target for Operator is on hold: the bootloader of the chosen device could not be unlocked. Other devices are being evaluated. No ARM hardware is available at the moment.
    • 
        
  • One shared key is used by the whole fleet, so a single operator cannot be revoked. This was an accepted choice.
    • 
        
  • Quality of the answers of the small model, its speed and its heat: not measured.
    • 
        
  • Wi-Fi, graphics, disk and Secure Boot on the LX15PRO: not verified.
    • 
        
  • Tools written by Cortega are not isolated at system level, and their check is only approximate.
    • 
        
  • The topic filter works on words: an off-topic question that uses only words known to Cortega can get through.
    • 
        
  • The web interface uses a self-made certificate, so the browser shows a warning the first time.

    2026-11-22 // Report 02
    
Citadel Father on Debian 13

    

    
Second report. Citadel Father now works as a control station on Debian 13, inside a virtual machine on the LX15PRO. It does not exist on real hardware yet. Estimated completion: about 50 percent (the method is at the end of this report).


    
Section // What was done
    

      
Base and virtual machine

      
    
        
  • Debian 13 is installed in a virtual machine. The services for Father, for the local AI engine and for Cortega start by themselves.
    • 
        
  • Father keeps what earlier reports described: operator connection, signed orders, expiry after 60 seconds, an activity log without target text, and the web interface with an access token.
    • 
        
  • Device management works in the virtual machine. It has never run on real hardware.
    • 
      

      
Citadel desktop

      
    
        
  • The look comes from this website: the emblem as wallpaper and the site fonts, plus a themed login screen and boot menu.
    • 
        
  • The desktop has no panel. Icons are drawn in detailed ASCII: Trash, Files, Resources, Terminal, AI Terminal, Network, Browser.
    • 
        
  • A script for the Italian keyboard is ready.
    • 
      

      
Cortega in Father mode

      
    
        
  • Father-only profiles, visible only when Father mode is on and never picked automatically.
    • 
        
  • In Father mode, Cortega talks about Father by default. She uses the knowledge base when it has the answer, and answers freely otherwise. The checks on authorised networks and the fixed reply to anyone claiming authority stay in the program.
    • 
        
  • The AI runs locally. A basic version works on any PC but is slow. A faster version needs a processor feature (AVX2) that the virtual machine must offer.
    • 
        
  • The AI of Father still waits for human input and does not act on its own.
    • 
      

      
Network and Tor

      
    
        
  • Network switch. Three modes. Off blocks every outgoing connection. Tor lets out only Tor. On is open, used for updates. The system starts offline.
    • 
        
  • Tor check. A check verifies that Tor works. The AI Terminal goes online to learn only if the check passes, otherwise it uses saved data.
    • 
        
  • Browser. Firefox set to go only through Tor, with DNS through Tor, and with WebRTC and location turned off. Google through Tor can show a CAPTCHA, and we do not try to bypass it.
    •

    2026-11-25 // Report 03
    
Father in the VM: installer, onion operators and node-map interface

    

    
Third report. Citadel Father still runs only inside a virtual machine. It now has one installer, its own certificate authority, one identity for each operator, updates only through Tor, and a new interface built on a node map. Readiness is 70 percent (52 items closed out of 74), measured with the method at the end.


    
Section // Installer, services and web UI
    

      
Installer

      
    
        
  • One installer. A single installer sets up Father on Debian 13 in 12 steps (0 to 11) and checks each one. It ran with every step OK in the virtual machine.
    • 
        
  • Tidy kit. Old versions and old files were moved out. Documents and the install guide are up to date. One start script is left for the virtual machine: 8 processors, 6 GB of memory, full HD.
    • 
        
  • AI services. The installer now turns on the local AI engine and Cortega. The AI engine had gone missing after an earlier install, and the new installer brings it back. Checked: it responds and Cortega answers.
    • 
        
  • Father as a service. It used to quit right after starting, because its console read empty input and stopped without an error, so nothing restarted it. A new option starts it without the console. Checked: the web interface is reachable.
    • 
        
  • Restarting the virtual machine. A reset used to stop the emulator and leave a frozen screen. Now the start script asks "restart the VM?" and reopens it. Checked.
    • 
      

      
Web UI

      
    
        
  • Own certificate authority. Father creates its own Citadel certificate authority and uses it to sign the certificate of the web interface. Only the browser of Father trusts it. On other machines the browser warning stays, on purpose. Checked.
    • 
        
  • Confirmation. Scanning the network and sending a message from the web interface need the word CONFERMA. So do authorising and revoking an operator. Checked.
    • 
        
  • Sessions. A web session lasts 1 hour and survives a restart of the service. Only a scrambled version of the session ID is saved on disk. Checked.
    • 
      

    

    


    
Section // Network, Tor and operators
    

      
Tor and updates

      
    
        
  • Updates through Tor. Updates come only from the official Debian onion mirrors. They work in Tor-only mode, and the normal Internet mirror fails on purpose. Checked.
    • 
        
  • Network switch. Fixed a bug: without admin rights, the status command showed "on" instead of the real mode. Checked.
    • 
        
  • Onion service of Father. It publishes only the operator connection. The web interface is not published on Tor. An operator reached Father through the onion address. Checked.
    • 
      

      
Operators

      
    
        
  • One identity per operator. The operator proves who it is by signing a challenge from Father with its own key. Father checks the signature and that the key is on the authorised list, then proves itself back with its own signature. Unauthorised operators are refused and logged by ID only.
    • 
        
  • Revocation. Removing an operator from the list closes its sessions at once and blocks it from reconnecting. The shared key stays only to recognise devices on the local network. Checked from Father Signals: authorise with CONFERMA, connect through onion, ping, revoke, refused reconnection.
    • 
        
  • Requests. An operator with a valid signature but an unknown key shows up in a REQUESTS screen, up to 20 requests for 24 hours. Father can authorise it with CONFERMA or ignore it.
    • 
      

      
Cortega as operator

      
    
        
  • Link to Father. Cortega connects to Father at every start and retries every 10 to 60 seconds. An order received is shown to the user, who can run it (still with a CONFERMA) or discard it. The first connection appears in REQUESTS.
    • 
        
  • Signature of Father. Cortega now checks the signature of Father. The old method is gone.
    • 
        
  • Operator test. A test inside Father runs 7 steps with a temporary key. Result: 7 of 7 passed. A refusal through onion takes about 4 seconds, and the first connection after authorisation about 11 seconds. Status and ping get a reply in under half a second. The test leaves no trace: its key is never added to the authorised list.
    • 
      

    

    


    
Section // Cortega
    

      
    
        
  • Understanding requests. Cortega now understands 35 of 35 test sentences, up from 34. A request to create a script that shows date and time is now read correctly. The more precise profile is now the default.
    • 
        
  • Tools she writes. Sum of 1 to 100: 20 seconds in total, correct result (5050). Prime numbers below 30: 38 seconds, correct result. Tools run in an isolated space inside the virtual machine.
    • 
        
  • Speed. The AI Terminal starts in 10 to 15 seconds. She reads a prompt at 117 tokens per second (the speed of writing was not read). The desktop stays smooth while Cortega writes.
    • 
        
  • AI engine. Decision: we keep llama.cpp for Father and we will not build our own engine in Go.
    • 
      

    

    


    
Section // Node-map interface
    

      
Citadel OS Father now follows one interface idea: a node map in red and black ASCII. The main map leads to the programs, and each program has its own map.

      

        
        
      

      
Main map, first view: CITADEL in the center, with PROGRAMS, FATHER SIGNALS, SYSTEM and NETWORK around it.

      
Main map with all branches open: programs, system settings and network modes. Tor only is selected, in green.

  • Main map. A full-screen map. CITADEL leads to PROGRAMS (AI Terminal, Terminal, Files, Browser), FATHER SIGNALS, NETWORK (Off, Tor only, Free with CONFERMA, Tor status) and SYSTEM (Resources, Keyboard and screen, Animation, Restart and Shutdown with CONFERMA). A program opens full-screen above the map, and closing it brings you back. The map dissolves into falling characters and builds itself again.
    • 
        
  • Workspaces. SYSTEM, SPACES, SPACE 1 to 4, with the active one in green.
    • 
        
  • Emblem. The central CITADEL node, the wallpaper, the login screen and the boot screen use an ASCII version of the Citadel logo. On the boot screen the emblem builds itself from falling characters. Checked.
    •

    •

    •

  • Animation load. The map now draws on a canvas with pre-drawn characters. In a test container, the browser's CPU use fell from 82 percent to 15 percent. A setting offers full (10 frames per second), reduced (4, no rain) or off. Not yet measured in the virtual machine.
